# Particle Studio --- Export System

## 1. Purpose

The export system converts particle data generated by the Python engine
into a shareable file in the format selected by the user. The primary
target of the first release is a single-file HTML output that recipients
can open without installing Particle Studio or Python. Terminal output
is a secondary target.

## 2. Supported formats

### 2.1 Standalone HTML

This is the primary sharing format.

-   Generated as a single `.html` file.
-   CSS, JavaScript, particle data, and playback settings are embedded
    in the file.
-   Requires no external server, Python installation, or additional
    asset folder.
-   Uses responsive design for desktop and mobile browsers.
-   Can be shared through messaging applications such as WhatsApp;
    recipients can open it in a browser on their device.

The animation should start automatically when the HTML file is opened.
Optional replay and pause controls may be provided.

### 2.2 Terminal output

This is a secondary and more limited output format.

-   A single executable `.cmd` file is the initial target.
-   The file opens in the Windows CMD environment and plays the
    animation in the terminal.
-   Terminal characters and ANSI color support should depend on the
    capabilities of the environment.
-   Terminal output is less accessible on mobile devices than HTML and
    should not be treated as the primary sharing format.

Note: `.cmd` is Windows-specific. Linux and macOS terminal support may
require a separate execution format or compatible launcher in a later
phase. Platform support must be validated while preserving the
single-file requirement.

## 3. Shared output contract

Both HTML and terminal exporters must use the same underlying data:

-   Particle coordinates and colors
-   Particle reveal order
-   Animation duration and frame/timing information
-   Background color
-   Output dimensions
-   Color mode
-   Schema version

Exporters must not re-analyze the image or generate their own particles.
These responsibilities belong to the Python core.

## 4. Contents of the HTML file

Conceptually, the single-file HTML output contains:

1.  HTML document structure
2.  Responsive style definitions
3.  Canvas or another suitable drawing surface
4.  Embedded particle data
5.  Animation playback code
6.  Initial/final state and playback settings
7.  Optional user controls

After generation, the output file must not depend on the source image or
the application's working directory.

## 5. Animation behavior

The target visual sequence for both output formats is:

1.  A black or very dark, nearly empty screen.
2.  The first particles gradually begin to appear.
3.  Particle density and the visible area progressively increase.
4.  The main object's silhouette and details become recognizable.
5.  Particles reach their final brightness and colors.
6.  The complete image remains visible on screen.

In monochrome mode, brightness gradually increases. In color mode,
particles may transition from dark initial tones to their sampled source
colors. Both modes use the same reveal timeline.

## 6. Mobile compatibility

Mandatory design targets for HTML output:

-   A drawing area that scales to the screen width
-   Portrait and landscape orientation support
-   Comfortable opening and viewing on touch devices
-   Adaptation to different pixel densities
-   No overflow or unwanted horizontal scrolling on small screens
-   Controlled particle count and drawing workload for animation
    performance

Mobile performance must be tested separately from desktop performance.

## 7. Performance and file size

-   Particle data should be serialized without unnecessary duplication.
-   Numeric data should be stored compactly where appropriate.
-   The HTML file must remain self-contained while keeping its size
    reasonable.
-   Reuse precomputed data where possible instead of recalculating every
    particle on every frame.
-   High particle counts must account for the memory and rendering
    capacity of the target device.

## 8. Error handling

Before export, validate the format, destination path, data integrity,
and particle count. On write failures, show a clear error to the user;
an incomplete or corrupted file must not be reported as a successful
export.

## 9. Acceptance criteria

-   HTML output is a single file and can be opened offline.
-   The HTML file works in desktop and mobile browsers.
-   Playback starts without requiring additional installation from the
    recipient.
-   Terminal output runs as a single `.cmd` file in supported Windows
    environments.
-   Both output formats are based on the same particle data and
    animation order.
-   Monochrome and color modes are supported.
